Реляционные БД хранят данные в виде таблиц с четкими связями между ними.

/*--------------------------------------------------------------------------------------------------------------------*/

Особенности реляционных БД:
1. Модель данных определяется заранее и является строго типизированной.
2. Данные хранятся в таблицах, состоящих из столбцов и строк.
3. На пересечении столбца и строки допускается только одно значение.
4. Каждый столбец имеет имя и определенный тип, которому следуют значения в строках.
5. Столбцы располагаются в определенном порядке, который определяется при создании таблицы.
6. Таблица может не иметь ни одной строки, но должна иметь хотя бы один столбец.
7. Запросы к БД возвращают результаты в виде таблиц.

/*--------------------------------------------------------------------------------------------------------------------*/

Язык SQL является универсальным для реляционных БД, но некоторые БД могут вносить изменения в язык SQL, тем самым
создавая диалекты или расширения языка.

Стандарт ANSI SQL-92 - это унифицированный набор команд и синтаксиса для работы с реляционными БД. Этот стандарт
поддерживается всем реляционными БД и включает в себя:
1. Базовые операции по работе с данными - SELECT, INSERT, UPDATE, DELETE.
2. Операции по управлению структурой таблиц - CREATE, ALTER, DROP.

/*--------------------------------------------------------------------------------------------------------------------*/

Таблица - это структурированный набор данных, организованный в виде строк и столбцов. Таблицы являются главным
строительным блоком реляционной модели. Таблица также может называться отношением или сущностью.

Основные свойства таблицы:
1. Имеет уникальное имя.
2. Содержит данные только об одной логической сущности.
3. Состоит из фиксированного набора столбцов и переменного числа строк.
4. Не зависит от порядка строк, то есть не имеет "первой" или "последней" записей.

/*--------------------------------------------------------------------------------------------------------------------*/

Столбец - это вертикальная структура таблицы, определяющая характеристику сущности. Столбец также может называться полем
или атрибутом.

Основные свойства столбца:
1. Имеет уникальное имя в пределах таблицы.
2. Определяется конкретным типом данных.
3. Может содержать ограничения.

/*--------------------------------------------------------------------------------------------------------------------*/

Строка - это отдельный экземпляр данных в таблице, представляющий конкретный объект сущности. Строка также может
называться записью или кортежем.

Основные свойства строки:
1. Состоит из набора значений, соответствующих типам всех столбцов таблицы.
2. Представляет собой отдельный объект.
3. В идеальной модели отсутствуют одинаковые строки.

/*--------------------------------------------------------------------------------------------------------------------*/

Результирующий набор - это временная таблица, возвращаемая в результате выполнения SQL-запроса.

Основные свойства результирующего набора:
1. Сохраняет структуру таблицы, то есть имена и типы столбцов.
2. Может содержать данные из нескольких таблиц.
3. Поддерживает сортировку и фильтрацию.
4. Существует в памяти временно во время выполнения операции.
5. Может быть пустым.

/*--------------------------------------------------------------------------------------------------------------------*/

Категории SQL-запросов:

1. DQL (Data Query Language) - язык запросов данных:
1.1 SELECT - чтение данных без изменения.

2. DML (Data Manipulation Language) - язык манипулирования данными:
2.1 INSERT - добавление новых записей.
2.2 UPDATE - изменение существующих данных.
2.3 DELETE - удаление записей.

3. DDL (Data Definition Language) - язык определения данных:
3.1 CREATE - создание объектов (таблиц, индексов).
3.2 ALTER - изменение структуры.
3.3 DROP - полное удаление объектов.
3.4 TRUNCATE - очистка таблицы (с сохранением структуры).

4. DCL (Data Control Language) - язык управления данными:
4.1 GRANT - предоставление прав.
4.2 REVOKE - отзыв прав.
4.3 DENY - запрет доступа.

5. TCL (Transaction Control Language) - язык управления транзакциями:
5.1 BEGIN - старт транзакции.
5.2 COMMIT - подтверждение изменений.
5.3 ROLLBACK - отмена изменений.

/*--------------------------------------------------------------------------------------------------------------------*/

Object-Relational Mapping (ORM) - это концепция, которая позволяет использовать объектно-ориентированный подход к работе
с БД. Она предоставляет абстракцию БД, позволяя взаимодействовать с ней через объекты и методы, вместо явного
использования SQL-запросов.

/*--------------------------------------------------------------------------------------------------------------------*/

Виды и примеры связей между таблицами:
1. Один к одному: таблица пользователей и таблица профилей пользователей.
2. Один ко многим: таблица пользователей и таблица постов пользователей.
3. Многие ко многим (требуется таблица-посредник): таблица постов и таблица тегов, требующие промежуточной таблицы
"пост - тег".

/*--------------------------------------------------------------------------------------------------------------------*/

Подзапрос - это запрос, вложенный в другой подзапрос.

Виды подзапросов по связи с внешним запросом:
1. Коррелированные подзапросы - это подзапросы, ссылающиеся на поля из внешнего запроса и выполняющиеся для каждой
записи внешнего запроса.
2. Некоррелированные подзапросы - это подзапросы, не ссылающиеся на поля из внешнего запроса и выполняющиеся один раз.

Виды подзапросов по размерности возвращаемого результирующего запроса:
1. Скалярные подзапросы - это подзапросы, возвращающие одну запись и одно поле.
2. Столбцовые подзапросы - это подзапросы, возвращающие несколько записей и одно поле.
3. Многостолбцовые (множественные) подзапросы - это подзапросы, возвращающие одну или несколько записей и несколько
полей.

/*--------------------------------------------------------------------------------------------------------------------*/

Нормализация данных - это процесс приведения таблиц к нормальным формам.

Нормальная форма - это требование, предъявляемое к структуре таблиц в теории реляционных БД для устранения из БД
избыточных функциональных зависимостей между полями.

Виды нормальных форм:
1. Первая нормальная форма (1NF):
1.1 Каждая ячейка таблицы содержит по одному значению, которые не являются составными данными.
1.2 В таблице есть PK.
1.3 В таблице все записи уникальные.
1.4 Каждое поле имеет свой отдельный тип.
1.5 Нет повторяющихся групп столбцов, например, "phone1", "phone2" и так далее.
2. Вторая нормальная форма (2NF) - только для таблиц с составными PK:
2.1 Таблица соответствует 1NF.
2.2 Таблица не содержит полей, которые зависят только лишь от части PK.
3. Третья нормальная форма (3NF):
3.1 Таблица соответствует 2NF.
3.2 Таблица не содержит полей, которые транзитивно зависят от первичного ключа, то есть когда одно поле зависит от
другого поля через третье поле.
4. Нормальная форма Бойса-Кодда (BCNF):
4.1 Таблица соответствует 3NF.
4.2 Каждое поле таблицы, от которого зависят другие поля, должно быть уникальным.
5. Четвертая нормальная форма (4NF):
5.1 Таблица соответствует BCNF.
5.2 В одной таблице не должно быть двух независимых списков, привязанных к одной записи.
6. Пятая нормальная форма (5NF):
6.1 Таблица соответствует 4NF.
6.2 Таблицу нельзя разбить на меньшие таблицы без потери данных, но если можно, то ее нужно разбить.

/*--------------------------------------------------------------------------------------------------------------------*/

Транзакция - это последовательность одной или нескольких операций, которые выполняются как единое целое, так что, либо
все операции выполнены успешно, либо ни одна из них не будет выполнена, при этом если при выполнении транзакции
происходит ошибка, то БД возвращается в исходное состояние до начала выполнения транзакции.

Свойства транзакций:
1. Атомарность (Atomicity): все операции в транзакции выполняются полностью или не выполняются вовсе.
2. Согласованность (Consistency): транзакция переводить БД из одного согласованного состояние в другое, соблюдая все
правила и ограничения.
3. Изолированность (Isolation): изменения, внесенные одной транзакцией, не видны другим транзакциям до тех пор, пока они
не будут зафиксированы.
4. Надежность (Durability): если транзакция завершена успешно, то внесенные ей изменения не могут быть потеряны ни при
каких обстоятельствах.

Уровни изоляции транзакций определяют как данные изолируются друг от друга при выполнении параллельных транзакций,
обеспечивая согласованность и целостность этих данных:
1. "Read Uncommitted": позволяет транзакциям читать изменения данных, которые еще не были зафиксированы. Этот уровень не
поддерживается в PostgreSQL (синтаксически поддерживается, но фактически работает как "Read Committed").
2. "Read Committed": позволяет транзакциям читать изменения, которые были зафиксированы. Это уровень по умолчанию в
PostgreSQL.
3. "Repeatable Read": гарантирует, что если чтение записи в транзакции выполняется больше одного раза, то эта транзакция
будет получать одни и те же данные каждый раз, так как параллельные транзакции не могут изменять или удалять эту запись.
4. "Serializable": обеспечивает полную изолированность транзакций, как если бы они выполнялись последовательно.

Уровни изоляции транзакций могут приводить к различным аномалиям:
1. "Dirty Read" (грязное чтение) - это чтение данных, которые были изменены другой транзакцией, но еще не зафиксированы
и впоследствии могут быть откатаны. Может произойти в "Read Uncommitted".
2. "Non-repeatable read" (неповторяющееся чтение) - это получение разных данных при повторном чтении одной и той же
записи, так как они были изменены и зафиксированы другой транзакцией. Может произойти в "Read Uncommitted" и
"Read Committed".
3. "Phantom Read" (фантомное чтение) - это получение разного количества записей при повторных запросах, так как другая
транзакция успела добавить или удалить записи и зафиксировать их. Может произойти в "Read Uncommitted", "Read Committed"
и "Repeatable Read" (но не в PostgreSQL).

Для обеспечения работы уровней изоляции транзакции используются блокировки записей и таблиц:
1. Объектные - на уровне приложения:
1.1 Оптимистические - данные не блокируются при чтении, а перед их сохранением проверяется, не были ли они изменены
другой транзакцией, обычно используя поле "version".
1.2 Пессимистические - при работе с данными они сразу блокируются для других транзакций.
2. Транзакционные - на уровне БД:
2.1 Управляемые - осуществляются при помощи специально написанных запросов, используя оператор "SELECT".
2.2 Автоматические - осуществляются самой БД автоматически при работе операторов "INSERT", "UPDATE" и "DELETE".
