2. Файл "tsconfig.json" содержит основные настройки TS для разработки. Для работы пакета reflect-metadata включены

"experimentalDecorators": true,
"emitDecoratorMetadata": true,
3. Файл "tsconfig.test.json" содержит отдельные настройки TS для тестов:
3.1 Берет все базовые настройки из файла "tsconfig.json".
3.2 TS проверяет типы, но не генерирует файлы .js.
3.3 Корнем проекта для этого конфига становится папка проекта (где лежит tsconfig). Это позволяет включать и папку
"src", и папку "__tests__", даже если они на одном уровне, и убирает конфликт вида "файл вне rootDir".
3.4 В тестовый проект входят весь код приложения из папки "src" и все тесты из папки "__tests__".
4. Файл "jest.config.ts" содержит настройки Jest. Запускаются тесты только из папки "__tests__/integration/".
5. Файл "eslint.config.mjs" содержит настройки ESLint:
5.1 Игнорируем папки "node_modules" и "dist".
5.2 Используем TS парсер.
5.3 Используем TS плагин и Prettier плагин.
5.4 Проверяем только файлы .ts.
5.5 Показываем ошибку, если форматирование не по правилам Prettier.
5.6 Показываем предупреждение для неиспользуемых переменных.
5.7 Показываем ошибку, если используется == или !=.
5.8 Отключаем правила ESLint, которые конфликтуют с Prettier.
5.9 В разделе "rules" добавлен раздел "simple-import-sort/imports" для настройки правил сортировки импортов при помощи
плагина eslint-plugin-simple-import-sort.
6. Файл ".prettierrc" содержит следующие правила:
6.1 Ставим точку с запятой в конце каждого выражения.
6.2 Используем одинарные кавычки вместо двойных.
6.3 Добавляем запятую после последнего элемента только в массивах и объектах.
6.4 Переносим код длиннее 120 символов на новую строку.
6.5 Используем два пробела для одного уровня отступа.
6.6 Добавляем пробелы внутри фигурных скобок.
6.7 Не ставим скобки вокруг аргумента стрелочной функции, если аргумент всего один.
7. Файл ".prettierignore" указывает какие файлы и папки должен игнорировать Prettier.
8. Файл "pnpm-workspace.yaml" создан автоматически после использования pnpm версии 11+. Этот файл нужен для конфигурации
монорепозиториев, то есть когда в одной папке несколько проектов. В этом файле есть секция "allowBuilds" необходимая для
настройки политик безопасности, поскольку теперь pnpm требует явного разрешения на выполнение post-install-скриптов
сборки для некоторых пакетов, которые потенциально могут выполнять вредоносный код. Например, для пакета @scarf/scarf
явно указано false, так как это пакет для аналитики.
