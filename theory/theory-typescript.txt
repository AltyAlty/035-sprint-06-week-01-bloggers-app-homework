Если нужно создать тип на основе какого-то типа "OriginalType", убрав из него какое-то поле "fieldToOmit", то можно
использовать это: "Omit<OriginalType, 'fieldToOmit'>".

Оператор is - это TS-оператор , который говорит компилятору, что если какая-то функция-предикат возвращает true, то
указанный переданный аргумент имеет указанный тип. is является одним из вариантов type guards. Пример:

function isNumber(value: string | number): value is number {
  return typeof value === 'number';
}

/*--------------------------------------------------------------------------------------------------------------------*/

В TS есть специальные модификаторы доступа к полям классов:
1. public: делает поле доступным всем.
2. private: делает поле доступным только внутри класса.
3. protected: делает поле доступным только в классе и дочерних классах.
4. readonly: делает поле доступным только для чтения, нельзя использовать для методов.

/*--------------------------------------------------------------------------------------------------------------------*/

В TS нельзя комбинировать символ "#" с модификаторами доступа к полям класса, кроме readonly.

/*--------------------------------------------------------------------------------------------------------------------*/

В TS для создания абстрактных классов есть синтаксис abstract, а для создания интерфейсов есть синтаксис interface,
только интерфейсы в ТС могут содержать поля (в классическом ООП - не могут).

В TS свойство абстрактного класса можно пометить как abstract, при этом сделать так, чтобы это свойство должно было быть
уточнено. Это может быть нужно, чтобы у любого наследника обязательно должно быть указано это свойство, когда
родительский класс не знает, какое у него должно быть начальное значение.

/*--------------------------------------------------------------------------------------------------------------------*/

Оператор implements - это TS-оператор, который реализует контракт, что какой-то класс обязан иметь все поля и методы из
указанного интерфейса или класса.

/*--------------------------------------------------------------------------------------------------------------------*/

Декораторы в TS - это функции, которые можно применять к классам, методам, свойствам и параметрам методов для их
модификации. Декораторы являются инструментом, позволяющим добавлять дополнительную функциональность к элементам
программы без изменения их исходного кода.

Виды декораторов:
1. Классовый декоратор: применяется к классу и может изменять или заменять его.
2. Декоратор метода: применяется к методу класса и позволяет изменить поведение метода.
3. Декоратор свойства: применяется к свойствам класса.
4. Декоратор параметра: применяется к параметрам метода.

При создании декораторов нужно использовать стандартную сигнатуру параметров:
1. Классовый декоратор: (target: Function).
2. Декоратор метода: (target: any, propertyKey: string, descriptor: PropertyDescriptor).
3. Декоратор свойства: (target: any, propertyKey: string).
4. Декоратор параметра: (target: any, propertyKey: string, parameterIndex: number).

Параметр "target" - это объект, на котором определено декорируемое свойство:
1. Для класса: функция-конструктор класса.
2. Для метода: прототип класса.
3. Для свойства: прототип класса.
4. Для статического метода: функция-конструктор класса.
5. Для параметра обычного метода: прототип класса.
6. Для параметра статического метода: функция-конструктор класса.

Параметр "propertyKey" - это имя свойства или метода в виде строки.

Параметр "descriptor" - это дескриптор из JS, описывающий декорируемый метод.

Параметр "parameterIndex" - это индекс декорируемого параметра в списке параметров.

TS-компилятор будет автоматически передавать параметры в декоратор при его запуске.

Пример декоратора метода:

function LogMethod(target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const originalMethod = descriptor.value;

    descriptor.value = function (...args: any[]) {
        console.log(`Вызов метода ${propertyKey} с аргументами: ${JSON.stringify(args)}`);
        return originalMethod.apply(this, args);
    };

    return descriptor;
}

class Calculator {
    @LogMethod
    add(a: number, b: number): number {
        return a + b;
    }
}

const calculator = new Calculator();
console.log(calculator.add(2, 3));

В данном примере декоратор создается примерно так:
1. Запускается функция "LogMethod()".
2. TS-компилятор передает "Calculator.prototype" в параметр "target".
3. TS-компилятор передает строку "add" в параметр "propertyKey".
4. TS-компилятор передает дескриптор метода "Calculator.prototype.add()" в параметр "descriptor".
5. В переменную "originalMethod" сохраняет оригинальный метод "Calculator.prototype.add()".
6. Изменяем дескриптор метода "Calculator.prototype.add()", чтобы в значение передать обертку над оригинальным методом
"Calculator.prototype.add()".
7. Срабатывает "return descriptor": важный шаг, чтобы TS обновил декорируемую цель - метод "Calculator.prototype.add()"
- при помощи метода "Object.defineProperty()": "Object.defineProperty(Calculator.prototype, 'add', descriptor)". Этот
шаг можно не делать, так как мы уже изменили объект дескриптора, но так делать считается хорошей практикой.

Если декоратор указывается без круглых скобок, например, "@Decorator", то TS вызовет его как функцию напрямую, передавая
в него аргументы в зависимости от того, куда декоратор поставлен. Если же декоратор указывается с круглыми скобками,
например, "@DecoratorFactory()", то TS сначала вызывает его как обычную функцию и то, что она вернет, TS потом уже
вызывает как декоратор.

Тип Record<Keys, Type> - это встроенный в TS тип для описания объекта-словаря, где заранее указывается тип всех его
ключей и тип всех его значений. Следующие две строки кода делают одно и тоже:
const constraints: { [p: string]: string } = error.constraints || {};
const constraints: Record<string, string> = error.constraints || {};
