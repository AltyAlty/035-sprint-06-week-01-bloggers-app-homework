Декоратор "@InjectModel()" - это декоратор из модуля @nestjs/mongoose, который работает через DI-контейнер NestJS. В
этом декораторе нужно указывать имя класса и это удобно делать через свойство "name" классов, которое содержит имя
класса в виде строки. Декоратор "@InjectModel()" просит NestJS найти и внедрить зарегистрированную через метод
"MongooseModule.forFeature()" в модуле готовую модель Mongoose.

/*--------------------------------------------------------------------------------------------------------------------*/

Если какой-то декоратор по факту возвращает другой декоратор, то такой декоратор называется фабрикой декораторов.

/*--------------------------------------------------------------------------------------------------------------------*/

Функция "Transform()" из библиотеки class-transformer является фабрикой декораторов, которая позволяет трансформировать
свойства. Если использовать несколько декораторов, которые внутри себя используют функцию "Transform()", то они будут
выполняться в порядке снизу вверх. Пример кастомного декоратора свойства, который трансформирует свойство в Input DTO,
используя функцию "Transform()":

import { Transform, TransformFnParams } from 'class-transformer';

export const Trim = () => {
  return Transform(({ value }: TransformFnParams) => {
    return typeof value === 'string' ? value.trim() : value;
  });
};

В этом примере:
1. Когда TS видит декоратор "@Trim()" рядом с каким-то свойством, то он вызывает функцию "Trim()".
2. Функция "Trim()" является фабрикой декораторов и внутри себя вызывает функцию "Transform()", в параметрах которой
указана callback-функция.
3. Функция "Transform()" возвращает функцию-декоратор свойства.
4. TS применяет возвращенную функцию-декоратор свойства к свойству.
5. Возвращенная функция-декоратор свойства записывает метаданные, что для указанного свойства есть указанная в
параметрах функции "Transform()" callback-функция, которую нужно вызывать при трансформации или десериализации.
6. Когда будет работать пайп "ValidationPipe", библиотека class-transformer прочитает указанные метаданные и применит
указанную в параметрах функции "Transform()" callback-функцию к свойству, чтобы трансформировать его.

/*--------------------------------------------------------------------------------------------------------------------*/

Функция "applyDecorators()" из NestJS является фабрикой декораторов, которая позволяет создавать декораторы путем
комбинации нескольких декораторов. Комбинируемые декораторы будут выполняться в порядке перечисления, то есть слева
направо. Но если использовать в функции "applyDecorators()" декораторы, которые внутри себя используют функцию
"Transform()", то такие декораторы будут отрабатывать первыми. Пример кастомного декоратора свойства, который
трансформирует и валидирует свойство в Input DTO, используя функцию "applyDecorators()":

import { applyDecorators } from '@nestjs/common';
import { IsString, Length } from 'class-validator';
import { Trim } from '../transform/trim';

export const IsStringWithTrim = (minLength: number, maxLength: number) =>
  applyDecorators(IsString(), Length(minLength, maxLength), Trim());

В этом примере:
1. Функции "IsString()", "Length()" и "Trim()" являются фабриками декораторов.
2. Когда TS видит декоратор "@IsStringWithTrim()" рядом с каким-то свойством, то он вызывает функцию
"IsStringWithTrim()".
3. Функция "IsStringWithTrim()" является фабрикой декораторов и вызывает внутри себя функции "IsString()", "Length()" и
"Trim()".
4. Каждая функция из "IsString()", "Length()" и "Trim()" возвращает свою функцию-декоратор свойства.
5. Функция "applyDecorators()" получает три возвращенные функции-декораторы свойства и возвращает новую комбинированную
функцию-декоратор свойства.
6. TS применяет возвращенную комбинированную функцию-декоратор свойства к свойству, последовательно применяя все три
исходные функции-декораторы свойства.
7. Каждая исходная функция-декоратор свойства записывает свои метаданные для свойства.
8. Когда будет работать пайп "ValidationPipe", сначала библиотека class-transformer прочитает указанные метаданные и
применит указанную в параметрах функции "Transform()" callback-функцию к свойству, чтобы трансформировать его.
9. Затем уже библиотека class-validator прочитает указанные метаданные и применит декораторы "IsString()" и "Length()"
из этой библиотеки к свойству, чтобы его валидировать.

Функция "createParamDecorator()" из NestJS является фабрикой декораторов, которая позволяет создавать декораторы
параметров методов контроллеров, способные извлекать данные из объектов запроса и передавать их напрямую в аргументы
методов контроллеров. Пример кастомного декоратора параметра метода контроллера, который извлекает свойство "user" из
объекта запроса и кладет его в параметр "user" метода контроллера, используя функцию "createParamDecorator()":

import { createParamDecorator, ExecutionContext } from '@nestjs/common';

export const User = createParamDecorator(
  (data: unknown, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    return request.user;
  },
);

@Get()
async findOne(@User() user: UserEntity) {
  console.log(user);
}

В этом примере:
1. При загрузке файла вызывается функция "createParamDecorator()", которая возвращает другую фабрику декораторов и
указывает внутри нее callback-функцию из своих параметров.
2. Возвращенная фабрика декораторов сохраняется в константу "User".
3. Когда TS видит декоратор "@User()" рядом с параметром "user" метода "findOne()" контроллера, то он вызывает функцию
"User()".
4. Функция "User()" возвращает функцию-декоратор параметра метода контроллера.
5. TS применяет возвращенную функцию-декоратор параметра метода контроллера к параметру "user" метода "findOne()"
контроллера.
6. Возвращенная функция-декоратор параметра записывает метаданные, что для параметра "user" метода "findOne()"
контроллера есть callback-функция, которую нужно вызывать при запросе.
7. Когда будет обрабатываться запрос, NestJS прочитает указанные метаданные, вызовет указанную в параметрах функции
"createParamDecorator()" callback-функцию с параметрами "undefined, ctx". Первый параметр "undefined", так как в
декоратор "@User()" ничего не было передано.
8. Указанная в параметрах функции "createParamDecorator()" callback-функция вернет свойство "user" из объекта запроса и
NestJS подставит его в параметр "user" метода "findOne()" контроллера.

Декоратор "@SetMetadata()" из NestJS является фабрикой декораторов, которая позволяет прикреплять метаданные к
контроллерам или методам контроллеров для дальнейшего использования этих метаданных гардами или перехватчиками. Первым
параметром декоратор "@SetMetadata()" получает имя ключа, по которому будут храниться метаданные, а вторым параметром -
сами метаданные. Класс "Reflector" из NestJS - это класс, используемый для чтения метаданных, ранее записанных через
декоратор "@SetMetadata()". Метод "getAllAndOverride()" экземпляра класса "Reflector" позволяет проверять метаданные по
указанному в первом параметре ключу для указанного во втором параметре наборе целевых объектов. Этот метод возвращает
первое значение не равное undefined в формате boolean. Пример кастомного декоратора метода контроллера, который делает
так, чтобы авторизационный гард не проводил проверку перед выполнением метода контроллера, используя декоратор
"@SetMetadata()":

import { SetMetadata } from '@nestjs/common';

export const IS_PUBLIC_KEY: string = 'isPublic';
export const Public = (): CustomDecorator<string> => SetMetadata(IS_PUBLIC_KEY, true);

@Public()
@Get()
async getAll(
  @Query() query: GetUsersQueryParams,
): Promise<PaginatedViewDto<UserViewDto[]>> {
  return this.usersQueryRepository.getAll(query);
}

В этом примере:
1. Когда TS видит декоратор "@Public()" рядом с методом "getAll()" контроллера, он вызывает функцию "Public()".
2. Функция "Public()" является фабрикой декораторов и вызывает функцию "SetMetadata()".
3. Функция "SetMetadata()" возвращает функцию-декоратор метода контроллера, которая может записывать метаданные в
формате ключ-значение, указанные в параметрах функции "SetMetadata()" и доступные ей через замыкание.
4. TS применяет возвращенную функцию-декоратор метода контроллера к методу "getAll()" контроллера.
5. Возвращенная функция-декоратор метода контроллера записывает метаданные, что метод "getAll()" контроллера имеет
данные в формате ключ-значение, где ключ - "isPublic", а значение - "true".
6. Когда будет обрабатываться запрос и сработает, например, гард для JWT-авторизации, то этот гард прочитает указанные
метаданные при помощи класса "Reflector".
7. Гард увидит, что ключ "isPublic" содержит значение "true", и пропустит JWT-авторизацию для метода "getAll()"
контроллера, тем самым допустив выполнение этого метода.

/*--------------------------------------------------------------------------------------------------------------------*/

Функция "Reflector.createDecorator()" из NestJS является фабрикой декораторов, которая позволяет прикреплять метаданные
к контроллерам или методам контроллеров для дальнейшего использования этих метаданных гардами или перехватчиками.
Главное отличие функции "Reflector.createDecorator()" от декоратора "@SetMetadata()" заключается в том, что функция
"Reflector.createDecorator()" сама создает уникальный ключ для хранения метаданных. Пример кастомного декоратора метода
контроллера, используя метод "Reflector.createDecorator()":

import { Reflector } from '@nestjs/core';

export const Roles = Reflector.createDecorator<string[]>();

@Post()
@Roles(['admin'])
async create(@Body() createCatDto: CreateCatDto) {
  this.catsService.create(createCatDto);
}

В этом примере:
1. При загрузке файла вызывается функция "Reflector.createDecorator()", которая возвращает другую фабрику
декораторов и указывает в ней, что она принимает метаданные в виде массива строк.
2. Функция "Reflector.createDecorator()" генерирует уникальный ключ, обычно в формате Symbol, для хранения метаданных по
нему, к которому есть доступ у возвращаемой фабрики декораторов через замыкание.
3. Возвращенная фабрика декораторов сохраняется в константу "Roles".
4. Когда TS видит декоратор "@Roles(['admin'])" рядом с методом "create()" контроллера, то он вызывает функцию
"Roles(['admin'])".
5. Функция "Roles(['admin'])" возвращает функцию-декоратор метода контроллера.
6. TS применяет возвращенную функцию-декоратор метода контроллера к методу "create()" контроллера.
7. Возвращенная функция-декоратор метода контроллера записывает метаданные, что метод "create()" контроллера имеет
данные в формате ключ-значение, где ключ - это сгенерированный функцией "Reflector.createDecorator()" уникальный ключ, а
значение - "['admin']".
8. Когда будет обрабатываться запрос и сработает, например, гард для JWT-авторизации, то этот гард прочитает указанные
метаданные при помощи класса "Reflector".
9. Гард сравнит роли пользователя, например, из объекта запроса, с разрешенными ролями, указанными в метаданных метода
"create()" контроллера, и разрешит выполнение метода "create()".

Функция "registerDecorator()" из библиотеки class-validator является функцией, которая позволяет регистрировать
кастомные валидационные декораторы свойств во внутреннем реестре библиотеки class-validator. Эта функция в качестве
параметра принимает объект с настройками этой функции.

/*--------------------------------------------------------------------------------------------------------------------*/

Декоратор "@ValidatorConstraint()" из библиотеки class-validator является декоратором, который позволяет регистрировать
классы как кастомные валидационные декораторы свойств во внутреннем реестре библиотеки class-validator. Этот декоратор
принимает объект с настройками в качестве параметра, где параметр "name" - это уникальное имя валидатора для внутренней
идентификации во внутреннем реестре библиотеки class-validator, а параметр "async" - это флаг, указывающий, что
валидация синхронная или нет.

Декоратор "@Res()" из NestJS внедряет объект ответа из Express.js, чтобы можно было использовать метода "res.cookie()"
для отправки данных клиенту через cookies. Этому декоратору можно передать опцию "{ passthrough: true }", чтобы указать
NestJS не отключать автоматическую отправку ответа через return.

Декоратор "@Headers()" из NestJS является декоратором, получающим HTTP-заголовка входящего запроса. Примеры:

@Get()
async get(@Headers('user-agent') userAgent: string) {}

@Get()
async getAll(@Headers() headers: Record<string, string>) {}
