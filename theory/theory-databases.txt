Типы БД:

1. Реляционные (SQL): данные лежат в таблицах, причем таблицы имеют строгие связи между собой. Примеры: PostgreSQL,
MySQL, Microsoft SQL Server, Oracle, SQLite, IBM Db2.

2. Документные: данные лежат в документах, похожих на JSON и не имеющих обязательных строгих связей между собой.
Примеры: MongoDB, Amazon DocumentDB, Couchbase, CouchDB.

3. Key-value (ключ-значение): данные лежат в виде словарей. Часто используются для дополнительных задач, так как не
удобны для сложных запросов. Примеры: Redis, Amazon DynamoDB, Riak, Memcached, KeyDB.

4. Колоночные (columnar): данные распределены по столбцам. Хорошо подходят под горизонтальное масштабирование, работу с
огромными объемами данных и запросами по известным паттернам доступа. Примеры: ClickHouse, Google BigQuery, Azure SQL
Data Warehouse.

5. Wide column: данные получаются большими объемами по ключам. Примеры: Apache Cassandra, ScyllaDB, HBase, BigTable.

6. Графовые: данные хранятся в виде связей подобных графам. Хорошо подходят для сложных сетей зависимостей и маршрутов.
Примеры: Neo4j, Amazon Neptune, Dgraph, Memgraph.

7. Временные ряды (time-series): данные категоризируются по меткам времени. Хорошо подходят для метрик, мониторинга и
датчиков. Примеры: InfluxDB, TimescaleDB, Prometheus, Druid, eXtremeDB, DolphinDB.

8. Поисковые (full-text search): часто используются как дополнение к основной БД с целью осуществления поиска и
фильтров. Примеры: Elasticsearch, OpenSearch, Solr, Algolia, Meilisearch.

9. Векторные: данные хранятся в виде чисел. Хорошо подходят для семантического поиска, рекомендаций, ИИ-приложений.
Примеры: Pinecone, Weaviate, Milvus, Qdrant.

10. Объектно-ориентированные: данные хранятся в виде объектов. Хорошо подходят для сложных объектных моделей в одном
домене. Примеры: ObjectStore, Versant, db4o, ZODB, Wakanda.

11. Иерархические: данные хранятся в виде дерева. Хорошо подходит для древовидных структур. Примеры: IBM Information
Management System (IMS).

12. Мультимодельные: в одной БД имеется поддержка нескольких моделей данных. Примеры: ArangoDB, Azure Cosmos DB,
Couchbase, OrientDB, Fauna, SurrealDB.

13. In-memory: данные в первую очередь держатся в оперативной памяти. Хорошо подходят если требуется очень низкая
задержка и высокая скорость на типичных операциях. Часто используется рядом с основной БД. Примеры: Redis, Memcached,
SAP HANA, VoltDB, Dragonfly.

14. NewSQL: SQL и модель, близкая к реляционной, с возможностью горизонтального масштабирования. Примеры: CockroachDB,
Google Spanner, TiDB, YugabyteDB.

/*--------------------------------------------------------------------------------------------------------------------*/

Вертикальное масштабирование БД: покупка дополнительной памяти, смена HDD на SSD, добавление оперативной памяти, и так
далее.

Горизонтальное масштабирование БД: добавить больше БД.

Репликация - это хранение одних и тех же данных на нескольких серверах.

Если есть несколько БД разных типов, например, MongoDB и PostgreSQL, то может создаваться отдельный бэкенд, который
будет осуществлять общение между этими БД. Смешивание нескольких типов БД в одном приложении называется полиглотным
хранением (Polyglot Persistence).

Несколько случаев, когда полиглотное хранение уместно:
1. Когда в приложении есть разные типы данных, которые получают преимущества или просто требуют использования каких-то
отдельных типов БД.
2. Когда приложение разделено на части, данные которых напрямую не связаны.
3. Когда нужно использовать новую БД, но нельзя отказаться от старой БД из-за легаси.

Если есть несколько БД одного и того же типа, например, MongoDB, то общение между ними желательно настраивать средствами
самих БД.

Предпочтительнее иметь несколько БД одного и того же типа, так как настройка общения между ними будет полагаться на
более надежные средства этих БД, чем на отдельно написанный бэкенд, который потенциально может содержать баги.

Если в БД становится очень много записей, то можно использовать шардирование - часть записей переносить в отдельную БД,
например, все записи с нечетными ID. Характеристика по которой должны разделяться данные должна быть удобна для
использования в бэкенде, чтобы легко можно было определить в какую БД делать запрос.

Партиционирование (секционирование) - это разделение большого количества записей в одной БД на несколько независимых
физических частей (секций или партиций), но с сохранением доступа к ним как к единому целому через стандартные
SQL-запросы.

/*--------------------------------------------------------------------------------------------------------------------*/

Если нужно работать сразу с несколькими разными БД, то можно использовать GUI СУБД DBeaver и отдельные JDBC драйвера для
работы с нужными БД.

/*--------------------------------------------------------------------------------------------------------------------*/

Если в БД оказываются бессвязные данные, например, лайки для несуществующих постов, то в таких ситуациях обычно либо
используют hard удаление таких данных, либо soft удаление, причем последнее решает наличие бессвязности таких данных.
