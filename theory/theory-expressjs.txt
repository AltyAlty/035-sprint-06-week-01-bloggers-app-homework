"Request" из Express.js используется для типизации параметра "req", а "Response" из Express.js используется для
типизации параметра "res".

Типизация дженериков первого параметра "req" хендлеров, передаваемых в методы "get()", "post()", "delete()" и "put()"
внутри роутеров из Express.js:
1. На первом месте уточняются URI-параметры.
2. На втором месте уточняется "ResBody". Относится к данным тела ответа, отправляемого клиенту.
3. На третьем месте уточняется "ReqBody". Относится к данным тела запроса, получаемого от клиента.
4. На четвертом месте уточняются query-параметры.

/*--------------------------------------------------------------------------------------------------------------------*/

Метод "sendStatus()" используется для отправки только статуса и соответствующего ему стандартного текстовое сообщения в
теле ответа.

/*--------------------------------------------------------------------------------------------------------------------*/

В некоторых ситуациях HTML-файлы, содержащие запросы на другой сервер, открываются локально, то есть через протокол
"file://". Такие ситуации могут вызывать CORS-ошибку, так как браузер блокирует запросы с протокола "file://" на
протокол "http://". Чтобы избежать такой ошибки, можно использовать CORS-middleware на сервере в Express.js:
"import cors from 'cors'" + "app.use(cors())".

/*--------------------------------------------------------------------------------------------------------------------*/

Для установки дополнительных заголовков в ответе в Express.js можно использовать метод "res.set('key', 'value')".

/*--------------------------------------------------------------------------------------------------------------------*/

Middlewares в Express.js могут получать три параметра:
1. Объект запроса.
2. Объект ответа.
3. Функция "next()" для передачи управления следующему обработчику.

В Express.js можно создавать два основных типа middlewares: application-level middlewares и error-handling middlewares.
Чтобы Express.js понимал, какой тип middleware используется для application-level middlewares нужно указывать 3
параметра (request, response, next), а для error-handling middlewares нужно указывать 4 параметра (error, request,
response, next).

/*--------------------------------------------------------------------------------------------------------------------*/

В Express.js можно определить IP-адрес через свойства "req.socket.localAddress", "req.socket.remoteAddress" и "req.ip".
Если используется прокси, то реальный IP-адрес можно найти в заголовке "x-forwarded-for" запроса, хотя поскольку
заголовки можно подделать, то IP-адрес там может быть поддельным. Если в Express.js установить "app.set('trust proxy',
true)", то свойство "req.ip" будет содержать реальный IP-адрес при использовании прокси.

"req.socket.localAddress" - это IP сервера.
"req.connection.remoteAddress" - это устаревший алиас к "req.socket.remoteAddress".
